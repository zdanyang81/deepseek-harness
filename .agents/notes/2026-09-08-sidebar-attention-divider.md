# Sidebar attention divider with strict timestamp ordering

English | [中文](2026-09-08-sidebar-attention-divider.zh.md)

Status: isolated candidate; not deployed.

## Decision

The office user explicitly selected strict `updatedAt` ordering instead of manually editable session order. The session catalog remains the authoritative data source through `useSessions`; the cutoff is browser viewing state in the registered workspace store, read through `useStore` and written through `actions.setAttentionCutoff`. Sessions newer than the cutoff are above the line and older ones are below. At equal timestamps an optional Session ID and before/after side locate the exact boundary in the existing ID-ascending display order. New activity reclassifies a session by its new timestamp without a membership list. Removing a boundary's anchor does not change that timestamp/identity ordering rule.

New browser viewing stores default to the flat view so the native attention divider is discoverable without a mode change. Existing saved workspace grouping remains an explicit preference and is not overwritten. The flat view renders one native divider. The grouped view retains workspace ordering and folding, sorts sessions within each group by timestamp, and offers the explicit `切到时间列表使用关注线` switch to the flat attention view instead of drawing a misleading global line across independent groups. The grouped-view switch has its own 32px bordered button with primary text, semibold weight, a tinted background and visible keyboard focus, making the mode change distinguishable from tertiary pagination controls. Search results never display the divider. This partially supersedes the session ordering decision in [Workspace Sidebar Order and Folding](implemented/feature/2026-08-11-workspace-sidebar-order-and-folding.md); its Host account and workspace folding decisions remain unchanged. No historical note is archived for this unshipped office candidate.

## Interaction and persistence

The divider occupies a real 32px CSS Grid track rather than overlaying a Session row boundary. FlatList owns the single transient preview; it places the divider and Session wrappers in distinct grid rows. The handle remains the same DOM child throughout a gesture, retaining pointer capture while only grid placement changes. Hit testing subtracts the measured reserved track from both pointer and row-midpoint coordinates, preventing the moving gap from repeatedly changing its own target. Cancellation restores the saved track and leaves adjacent Session click targets intact. Only the 28×20 handle owns the 450ms pointer hold; its right edge shares the Session time column's 8px inset and it has no visible 关注/可忽略 caption. Session rows keep their click, menu and hover behavior; session native drag is disabled. Movement before activation, pointer cancellation, capture loss, Escape, window blur, outside release, component disposal and catalog timestamp changes cancel without committing. Edge scrolling operates only on the existing list container, leaving catalog pagination to its existing scroll handler. Tail-only catalog paging preserves the gesture, capture and preview if the complete previously observed prefix matches by ID and timestamp at every position; movement reads fresh row geometry and can target the new page. Each accepted page extends the protected prefix, so later deletion or mutation of even a newly appended row cancels. Reconciliation runs on catalog updates and again during gesture events, including pointerup; effect cleanup is reserved for disposal, not pagination. A moved gesture commits once on pointerup. Keyboard arrows/Home/End provide equivalent explicit cutoff moves.

The cutoff is local to this browser and origin, not synchronized to other devices. First use or missing legacy state initializes to the mount's current time and persists it once, leaving older sessions below the line. Valid saved numeric cutoffs preserve their old meaning. A cutoff before the loaded catalog is preserved with a paging explanation; loading more does not reset it. Code rollback does not delete this viewing state or alter sessions. The complete previous `client-lib` is the rollback unit; only browser JS/map change in the candidate.

## Verification

The baseline native browser build is compared against the production source map and generated JavaScript, preserving the deployed paging, scroll and search behavior. The composed sidebar never had a working first-prompt loader: the runtime API and list metadata do not implement it. Removing its dead injection, required prop and unsupported metadata read aligns the browser with that ABI without changing displayed titles or inventing an API. Optional row-level display helpers remain untouched; this change does not claim first-prompt support. Focused tests cover cutoff projection, tied times, persistence, pointer ownership, cancellation and edge scrolling, alongside updated workspace browser behavior tests. A separate isolated browser can route only the candidate JavaScript at the existing 3080 URL; that is candidate verification, not production activation. Activation and original-URL production acceptance remain with the coordinating parent.

The time-only product rule in this candidate is reversed by [Sidebar attention Manual order and independent gray line](implemented/feature/2026-09-09-sidebar-attention-manual-restore.md). Last-updated cutoff, promotion, and divider presentation remain.
