# Agent Note: 侧栏关注分界线手柄对齐

Status: implemented

[English](2026-09-09-sidebar-attention-handle-alignment.md) | 中文

## 问题

灰色关注分界线已经占用独立的 32px 行，按下后即可拖动。可见的「↑ 关注 · 可忽略 ↓」以及更早历史提示会与 Session 标题抢位置，居中的 44×24 手柄也不在 Session 时间列上。

## 决策

分界线仍占用一条 32px CSS Grid 轨道，并沿用按下即拖、取消、键盘与本机浏览器截止点规则。它不再渲染可见文案。手柄改为 28×20 按钮。`.time` 没有固定列宽，因此手柄右缘与时间列共用 8px 内边距：分界线使用 `.sessionRow` 的 `padding: 0 8px` 作为 `margin-inline: 8px`，并以 `justify-content: flex-end` 右对齐。关注含义仍由手柄的 `aria-label` 与 `title` 提供，包括分界点落在未加载历史时的说明。这是办公室关注分界线的展示调整；它不恢复 Session 手动排序，也不改变 [Workspace 侧边栏顺序与折叠](2026-08-11-workspace-sidebar-order-and-folding.zh.md) 的 Host Workspace 顺序。

## 备选方案

**保留可见文案，只缩小手柄。** 未采用：产品要求灰线本身不出现「关注/可忽略」文字；手柄变小但仍挨着同一条文案，还是会占时间列。

**用绝对定位和写死的右侧偏移放手柄。** 未采用：时间列右缘已经由共享的 8px 行内边距决定；写死像素会在列表内边距或滚动条变量变化时走偏。

**把说明做成第二个可见控件。** 未采用：手柄已经持有拖动目标、键盘焦点和无障碍名称；再加一个控件会在预留行里多出一个点击区域。

**按每个时间字符串的中心对齐手柄。** 未采用：`.time` 随内容伸缩，只有共享的 8px 右内边距在 `12:03` 和 `昨天` 之间都稳定；可验收的几何是右缘对齐 ±1px。

**使用 24×18 手柄。** 未作为主尺寸采用：触屏拖动目标过小，容易点空；28×20 仍小于原来的 44×24。

## 后果

视力正常的用户从灰线和落在时间列右缘的 28×20 手柄判断截止位置。读屏与工具提示用户仍能听到关注含义。分界点落在未加载历史时，行内不再出现提示文案；在继续加载之前，只有手柄 `title` 说明这一点。

## 测试

CSS 契约测试固定 32px 轨道、28×20 手柄、共享 8px 内边距、右缘对齐，以及不存在 `.caption` 规则。分界线测试保留按下即拖、取消、分页和键盘覆盖，并新增断言：可见的「关注/可忽略」与更早历史文案已消失，同时无障碍名称仍在。
