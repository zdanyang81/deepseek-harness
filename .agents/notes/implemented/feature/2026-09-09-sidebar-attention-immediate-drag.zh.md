# Agent Note: 侧栏关注分界线按下即拖

Status: implemented

[English](2026-09-09-sidebar-attention-immediate-drag.md) | 中文

## 问题

灰色关注分界线以前要长按 450ms 才会跟着指针走。办公室用户觉得这个等待太久，要求按下手柄就能拖这条线。

## 决策

在 28×20 手柄上 pointerdown 立即开始拖动：捕获指针、显示按下字形，并跟随后续移动。没有移动的短按仍不保存。Escape、失焦、pointercancel、丢失捕获、在列表外松开，以及已见前缀变化，仍恢复已保存位置。手动排序和最近更新继续各自保存边界。展示规则仍在[侧栏关注分界线手柄对齐](2026-09-09-sidebar-attention-handle-alignment.zh.md)；手动排序仍在[侧栏关注分界线的手动排序与独立灰线](2026-09-09-sidebar-attention-manual-restore.zh.md)。

## 备选方案

**继续用 450ms 长按，避免短按开始拖动。** 未采用：用户要求按下手柄就能拖。

**在 pointerdown 时直接保存，不要求移动。** 未采用：点一下手柄就会改已保存位置。

**移动若干像素后才开始拖。** 未作为主规则采用：要求的是按下即拖，而不是另一种等待；现有 3px 阈值仍决定松手时是否保存。

## 后果

按下手柄立刻接管灰线，不必再等。误点仍不改已保存位置。键盘、分页、overlay 定位和两种排序保持不变。会让会话让位的 live 预览见[侧栏关注分界线列表内跟手](2026-09-09-sidebar-attention-list-walk.zh.md)。

## 测试

分界线测试覆盖按下后拖动再保存、按下未移动不保存，以及 Escape 与 pointercancel 恢复已保存位置。工作区浏览器测试沿用同一条按下即拖路径，不再等待 450ms。
